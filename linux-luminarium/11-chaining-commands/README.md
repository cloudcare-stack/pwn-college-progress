## What I Learned

### 1. Chaining with Semicolons

**Concepts:**

* The semicolon `;` allows multiple commands to be entered on one command line.
* Commands execute sequentially from left to right.
* The second command runs regardless of whether the first command succeeds or fails.
* This is similar to running one command, pressing Enter, and then running another.

**Command used:**

```bash
/challenge/pwn; /challenge/college
```

**Syntax:**

```bash
command1; command2
```

---

### 2. Building on Success

**Concepts:**

* The `&&` operator runs the second command only if the first command succeeds.
* A successful Linux command normally returns exit code `0`.
* This is useful when one operation should depend on another operation completing successfully.

**Command used:**

```bash
/challenge/first-success && /challenge/second
```

**Syntax:**

```bash
command1 && command2
```

**Meaning:**

```text
command1 succeeds → command2 runs
command1 fails    → command2 does not run
```

---

### 3. Handling Failure

**Concepts:**

* The `||` operator runs the second command only if the first command fails.
* Failure normally means a non-zero exit code.
* This is useful for fallback commands and error handling.

**Command used:**

```bash
/challenge/first-failure || /challenge/second
```

**Syntax:**

```bash
command1 || command2
```

**Meaning:**

```text
command1 succeeds → command2 does not run
command1 fails    → command2 runs
```

### Chaining Operator Summary

| Operator | Meaning | When Command 2 Runs     |    |                      |
| -------- | ------- | ----------------------- | -- | -------------------- |
| `;`      | Then    | Always                  |    |                      |
| `&&`     | AND     | When command 1 succeeds |    |                      |
| `        |         | `                       | OR | When command 1 fails |

### 4. Your First Shell Script

**Concepts:**

* A shell script is a text file containing shell commands.
* Bash can read the file and execute its commands sequentially.
* `>` creates or overwrites a file.
* `>>` appends additional data to a file.

**Script created:**

```bash
/challenge/pwn
/challenge/college
```

**Commands used:**

```bash
echo '/challenge/pwn' > x.sh
echo '/challenge/college' >> x.sh
cat x.sh
bash x.sh
```

**Important:**

```text
>   = overwrite
>>  = append
```

Running:

```bash
bash x.sh
```

tells Bash to read and execute the commands stored in `x.sh`.

---

### 5. Redirecting Script Output

**Concepts:**

* A shell script can be treated like another command.
* The output generated by multiple commands inside a script can be sent through one pipe.
* `|` connects the standard output of one command to the standard input of another.

**Script:**

```bash
/challenge/pwn
/challenge/college
```

**Command used:**

```bash
bash x.sh | /challenge/solve
```

This sends the combined output produced by `x.sh` into `/challenge/solve`.

**Flow:**

```text
/challenge/pwn ─────┐
                    ├── x.sh ──> | ──> /challenge/solve
/challenge/college ─┘
```

### 6. Executable Shell Scripts

**Concepts:**

* A script can be given executable permission with `chmod +x`.
* An executable script can be launched directly instead of explicitly using `bash`.
* `./` refers to the current directory.

**Commands used:**

```bash
echo '/challenge/solve' > x.sh
chmod +x x.sh
./x.sh
```

**Difference:**

```bash
bash x.sh
```

explicitly starts Bash and gives `x.sh` to it.

```bash
./x.sh
```

executes the script directly from the current directory.

### 7. Understanding Shebangs

**Concepts:**

* A shebang tells Linux which interpreter should execute a script.
* A shebang begins with `#!`.
* It must appear on the very first line of the file.
* There should be no blank lines or spaces before the shebang.

**Bash shebang:**

```bash
#!/bin/bash
```

**Script created:**

```bash
#!/bin/bash
echo "hack the planet"
```

**Commands used:**

```bash
chmod +x solve.sh
/challenge/run
```

**Common shebangs:**

```bash
#!/bin/bash
#!/bin/sh
#!/usr/bin/python3
```

### 8. Scripting with Arguments

**Concepts:**

* Shell scripts can receive command-line arguments.
* Bash provides special positional variables for accessing them.
* `$1` is the first argument.
* `$2` is the second argument.
* `$3` is the third argument, and so on.

**Script:**

```bash
#!/bin/bash
echo "$2 $1"
```

**Example:**

```bash
bash solve.sh pwn college
```

Arguments become:

```text
$1 = pwn
$2 = college
```

Output:

```text
college pwn
```

**Important lesson:**

```bash
$2 $1
```

tries to execute the contents of `$2` as a command.

Instead:

```bash
echo "$2 $1"
```

prints the arguments.

### 9. Scripting with Conditionals

**Concepts:**

* Bash supports `if` statements for conditional execution.
* `[ ... ]` can test a condition.
* Bash requires spaces around `[` and `]`.
* `then` begins the commands that execute when the condition is true.
* `fi` ends the `if` statement.

**Script:**

```bash
#!/bin/bash

if [ "$1" == "pwn" ]
then
    echo "college"
fi
```

**Behavior:**

```text
Input: pwn → college
Other input → no output
```

**General syntax:**

```bash
if [ condition ]
then
    command
fi
```

Correct:

```bash
if [ "$1" == "pwn" ]
```

Incorrect:

```bash
if [$1 == pwn]
```

---

### 10. Scripting with Default Cases

**Concepts:**

* `else` handles the default case when an `if` condition is false.
* An `else` block does not require another condition.
* The entire structure still ends with `fi`.

**Script:**

```bash
#!/bin/bash

if [ "$1" == "pwn" ]
then
    echo "college"
else
    echo "nope"
fi
```

**Behavior:**

```text
pwn       → college
anything  → nope
```

**General syntax:**

```bash
if [ condition ]
then
    command_if_true
else
    command_if_false
fi
```

---

### 11. Scripting with Multiple Conditions

**Concepts:**

* `elif` means **else if**.
* It allows multiple conditions to be tested.
* Conditions are evaluated from top to bottom.
* Bash executes the first matching block.
* `else` handles anything that did not match an earlier condition.

**Script:**

```bash
#!/bin/bash

if [ "$1" == "pwn" ]
then
    echo "college"
elif [ "$1" == "hack" ]
then
    echo "the planet"
elif [ "$1" == "learn" ]
then
    echo "linux"
else
    echo "unknown"
fi
```

**Behavior:**

```text
pwn   → college
hack  → the planet
learn → linux
other → unknown
```

**General structure:**

```bash
if [ condition1 ]
then
    command1
elif [ condition2 ]
then
    command2
elif [ condition3 ]
then
    command3
else
    default_command
fi
```

### 12. Reading Shell Scripts

**Concepts:**

* Shell scripts are normally text files and can be inspected when read permissions allow it.
* Reading source code can reveal how a program works and what input it expects.
* `cat` can display a shell script's source code.
* The `read` command accepts user input and stores it in a variable.

**Command used:**

```bash
cat /challenge/run
```

The script contained logic similar to:

```bash
read GUESS

if [ "$GUESS" == "hack the PLANET" ]
then
    echo "CORRECT! Your flag:"
    cat /flag
else
    echo "Read the /challenge/run file to figure out the correct password!"
fi
```

From the source code, the expected password could be identified.

Then the challenge was executed with:

```bash
/challenge/run
```

and the expected input was provided.

**Important lesson:**

Before guessing how a readable script works, inspect its source code:

```bash
cat script.sh
```

Other tools such as `less` can also be useful for reading longer scripts.

./script.sh

```bash
if [ condition ]
then
    command
fi
```

```bash
if [ condition ]
then
    command1
else
    command2
fi
```

```bash
if [ condition1 ]
then
    command1
elif [ condition2 ]
then
    command2
else
    default_command
fi
```

```bash
command1; command2
command1 && command2
command1 || command2
```

## Key Takeaways

* `;` runs commands sequentially regardless of success or failure.
* `&&` continues only after success.
* `||` continues only after failure.
* Shell scripts store multiple commands in reusable files.
* `>` overwrites a file, while `>>` appends to it.
* Scripts can participate in pipes and redirections just like other commands.
* `chmod +x` makes a script executable.
* `./script.sh` executes a script from the current directory.
* `#!` specifies the script's interpreter.
* `$1`, `$2`, `$3`, etc. represent positional arguments.
* `if`, `elif`, and `else` provide conditional logic.
* Bash syntax is sensitive to spacing, especially around `[ ]`.
* Reading shell scripts is useful for understanding program behavior and debugging.
